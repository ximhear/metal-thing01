# 브레인스토밍

발산(많이, 넓게)과 수렴(기준을 세워 고르기)을 분리해서 진행한다. 발산하는 동안에는 평가하지 않는다.

## 진행 순서

1. **주제 정리**: 무엇에 대한 아이디어인지, 목표와 제약(플랫폼, 기간, 기술: 예를 들어 Metal/SwiftUI)을 한 문장으로 정리한다. 모르는 게 결정적이면 한 번만 묻고, 아니면 가정을 밝히고 진행한다.
2. **발산**: 최소 12개 아이디어를 낸다. 한 방향에 몰리지 않도록 여러 축을 일부러 돌린다.
   - 사용자 축: 초보 / 전문가 / 아이 / 창작자 / 업무용
   - 형태 축: 도구, 장난감, 게임, 시각화, 교육, 유틸리티
   - 기법: SCAMPER(대체·결합·적용·변형·다른 용도·제거·뒤집기), "만약 ~라면?", 극단화(10배 크게, 기능 하나만), 다른 분야에서 빌려오기
   - 최소 2~3개는 일부러 엉뚱한 아이디어로 넣는다.
   각 아이디어는 이름 + 한 줄 설명 + "왜 재미있거나 쓸모 있는지" 한 줄.
3. **묶기**: 비슷한 것끼리 3~5개 그룹으로 묶고, 그룹마다 이름을 붙인다.
4. **수렴**: 기준을 표로 평가한다. 기본 기준(사용자가 바꿀 수 있음):
   | 아이디어 | 사용자 가치 | 독창성 | 구현 난이도(낮을수록 좋음) | 기술 학습 가치 | 첫 버전까지 시간 |
   각 1~5점, 짧은 근거 포함.
5. **추천**: 상위 1~3개를 추천하고, 1순위를 가장 작게 시험해 볼 방법(1~2일짜리 프로토타입)을 제시한다.
6. **다음 단계**: 고른 아이디어는 `product-planner` 스킬로 기획서로 만들자고 제안한다.

## 원칙

- 기존 앱이나 게임을 그대로 베끼는 아이디어는 내지 않는다. 장르·메커니즘을 빌리는 건 괜찮다.
- 사용자가 낸 아이디어는 비판하기 전에 먼저 확장한다("이걸 더 밀면…").
- 결과가 길어지면 `docs/ideas/<주제>.md`로 저장한다.
