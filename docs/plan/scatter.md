# Scatter — 천만 점 플로터 (가칭)

## 한 줄 요약
데이터를 다루는 macOS 사용자가 수백만~수천만 행짜리 CSV를 끌어다 놓으면 몇 초 안에 산점도·선 그래프로 보고, 끊김 없이 확대·이동하며 패턴을 찾을 수 있다.

## 문제
- Numbers는 행 수 제한(약 100만 행) 때문에 큰 파일을 열지 못하고, Excel도 수십만 점 차트부터 느려진다.
- Python(matplotlib)은 그릴 수는 있지만 매번 코드를 써야 하고, 천만 점에서는 확대·이동이 사실상 불가능하다.
- 결과적으로 로그, 센서, 실험, 금융 틱 데이터를 "일단 한번 보는" 가벼운 도구가 없다.

## 대상 사용자
1. **개발자·엔지니어 (주)**: 서버 지연 시간 로그, 센서·측정값 CSV를 받아 이상 구간을 찾고 싶다. 터미널에서 CSV를 만들고 바로 보고 싶다.
2. **연구자·분석가**: 실험·시뮬레이션 결과 수백만 행의 분포를 빠르게 확인하고, 보고서에 넣을 그림을 저장하고 싶다.

## 목표와 성공 지표
- 목표: "파일 열기 → 패턴 발견"까지의 시간을 분 단위에서 초 단위로 줄인다.
- 지표 (M2 Pro 기준):
  - 1,000만 행 × 2열 CSV(약 250MB) 불러오기 **5초 이내**
  - 1,000만 점 확대·이동 중 **60fps 유지** (프레임 시간 16.7ms 이하)
  - 처음 쓰는 사용자가 설명 없이 **1분 안에** 첫 그래프를 띄움
  - 메모리: 데이터 크기의 3배 이하

## 범위
### MVP (반드시)
1. CSV/TSV 열기: 창에 끌어다 놓기, ⌘O, Finder에서 "다음으로 열기". 첫 줄 헤더 자동 감지, 구분자(`,` `\t` `;`) 자동 감지.
2. 빠른 병렬 파싱: 파일을 메모리 매핑하고 여러 코어로 나눠 숫자 열만 추출. 진행률 표시.
3. 열 선택: 사이드바에서 X, Y 열을 고름. 헤더가 없으면 "열 1, 열 2…". X를 "행 번호"로도 선택 가능.
4. 두 가지 그리기 방식
   - **밀도 산점도** (기본): 점을 가산 블렌딩으로 누적한 뒤 로그 스케일 컬러맵으로 표시. 점이 겹쳐도 많은 곳이 밝게 보인다.
   - **선 그래프**: 행 순서대로 잇기(시계열용).
5. 탐색: 트랙패드 핀치·스크롤로 확대·이동, 드래그로 이동, 더블클릭으로 전체 보기, X축만/Y축만 확대(⌥ / ⇧ 누른 채).
6. 축과 눈금: 현재 보이는 범위에 맞는 눈금과 숫자 라벨, 격자선.
7. 커서 위치 표시: 마우스 아래 좌표를 데이터 단위로 표시.
8. 정보 패널: 행 수, 건너뛴 행 수(숫자가 아닌 값), 각 열의 최소·최대, 불러오기 시간.
9. 이미지 저장: 현재 화면을 PNG로 (⌘E).
10. 빈 상태: 처음 실행하면 "CSV를 여기에 놓으세요" + 예제 데이터 만들기 버튼(천만 점 합성 데이터).

### 다음 단계 (있으면 좋음)
- 세 번째 열로 색 입히기, 점 크기·투명도 조절
- 가장 가까운 점 찾기(호버 시 원래 행 내용 표시)
- 범위 선택 → 선택 구간 통계, 선택 행만 CSV로 내보내기
- 여러 Y 열 겹쳐 그리기, 히스토그램 패널
- 날짜·시간 열 인식
- 메모리보다 큰 파일(스트리밍·다운샘플 피라미드), Parquet 지원
- 명령줄에서 열기: `scatter data.csv`

### 하지 않을 것 (Non-goals)
- 데이터 편집, 스프레드시트 기능
- 통계 분석·회귀 등 분석 도구
- 클라우드·공유·협업
- iOS 버전

## 사용자 스토리와 수용 기준
- **[S1] 큰 파일 열기** — 엔지니어로서 천만 행 CSV를 창에 끌어다 놓고 바로 보고 싶다, 코드를 짜지 않고 확인하기 위해.
  - Given 1,000만 행 × 2열 숫자 CSV / When 창에 놓으면 / Then 진행률이 보이고 5초 안에 밀도 산점도가 전체 범위로 나타난다.
- **[S2] 확대해서 이상 구간 찾기** — 분석가로서 그래프를 확대·이동해 특이한 구간을 찾고 싶다.
  - Given 천만 점이 그려진 상태 / When 핀치·스크롤로 확대·이동하면 / Then 끊김 없이(60fps) 따라오고 축 눈금이 실제 값에 맞게 바뀐다. 더블클릭하면 전체 보기로 돌아온다.
- **[S3] 다른 열 보기** — 사용자로서 X·Y로 쓸 열을 바꾸고 싶다.
  - Given 5개 숫자 열이 있는 CSV / When 사이드바에서 Y 열을 바꾸면 / Then 0.5초 안에 다시 그려지고 범위가 새 열에 맞춰진다.
- **[S4] 시계열은 선으로** — 엔지니어로서 시간 순서 데이터를 선 그래프로 보고 싶다.
  - Given X = 행 번호 / When 선 그래프로 바꾸면 / Then 행 순서대로 연결된 선이 그려지고 확대해도 60fps를 유지한다.
- **[S5] 정확한 값 읽기** — 분석가로서 커서 위치의 값을 알고 싶다.
  - When 그래프 위로 마우스를 움직이면 / Then 커서 아래 X·Y 값이 데이터 단위로 표시된다(유효 숫자 6자리).
- **[S6] 그림 저장** — 연구자로서 지금 보이는 그래프를 보고서용 이미지로 저장하고 싶다.
  - When ⌘E → 위치 선택 / Then 축·라벨이 포함된 PNG가 화면과 같은 모습으로 저장된다.
- **[S7] 지저분한 파일** — 사용자로서 빈 칸·문자열이 섞인 파일도 열고 싶다.
  - Given 일부 행에 숫자가 아닌 값 / When 열면 / Then 해당 행은 건너뛰고, 건너뛴 행 수가 정보 패널에 표시된다. 앱은 멈추지 않는다.

> `app-user-review` 평가 과제: S1(파일 열기), S2(확대·탐색), S3(열 바꾸기), S6(저장), 그리고 "처음 실행해서 설명 없이 첫 그래프 띄우기".

## 화면 흐름
```
[빈 창: 놓기 안내 + "예제 데이터" 버튼]
        │ 파일 놓기 / ⌘O / 예제
        ▼
[불러오는 중: 진행률, 파일 이름, 취소]
        ▼
[메인 창]
 ├─ 사이드바: 파일 정보 · X/Y 열 선택 · 그리기 방식(밀도/선) · 열 통계
 ├─ 플롯 영역(Metal): 점·선, 격자, 축 눈금·라벨, 커서 좌표
 └─ 툴바: 열기, 전체 보기, 그리기 방식, PNG 저장
```

## 기술 고려사항
- **플랫폼**: macOS 15 이상, Apple silicon 우선. 개발 환경은 Xcode 27.2, Swift 6.4, M2 Pro.
- **구조**: SwiftUI 앱(`DocumentGroup` 대신 단순 `WindowGroup` + 파일 열기). 플롯은 `MTKView`를 `NSViewRepresentable`로 감쌈. 축·라벨은 SwiftUI `Canvas` 오버레이.
- **데이터 정밀도**: GPU에는 Float32로 올리되, 각 열의 최소값을 빼고(Double로 계산) 올려서 큰 값(예: 유닉스 시간 1.7e9)의 정밀도 손실을 줄인다. 뷰 변환도 같은 기준점으로 계산.
- **렌더링**
  - 밀도 모드: 점을 `R32Float`(또는 `R16Float`) 누적 텍스처에 가산 블렌딩으로 그린 뒤, 전체 화면 패스에서 `log(1+count)`를 컬러맵으로 변환. 누적 최대값은 컴퓨트 축소 연산으로 구함.
  - 선 모드: `lineStrip`. 너무 촘촘하면 나중에 min/max 다운샘플.
  - 뷰 변환은 uniform으로만 바꾸고 정점 버퍼는 다시 만들지 않는다.
- **파싱**: `mmap` + 줄 경계로 청크를 나눠 `DispatchQueue.concurrentPerform`으로 병렬 파싱. 직접 짠 숫자 파서(`strtod` 대비 빠른 경로).
- **저장**: 사용자 데이터는 저장하지 않음. 최근 파일만 기억.
- **권한**: 샌드박스 + 사용자가 고른 파일 읽기 권한만.
- **프로젝트 생성**: `xcodegen`으로 `project.yml`에서 Xcode 프로젝트 생성.

## 위험과 가정
- 가정: 대부분의 사용 파일은 메모리에 들어간다(수 GB 이하). 숫자 열 위주다. 첫 줄이 헤더이거나 숫자다.
- 위험
  - **Float32 정밀도** — 확대를 아주 많이 하면 점이 계단처럼 보임. 대응: 열 최소값 기준 오프셋, 더 필요하면 화면 기준점 재설정.
  - **파싱 속도 목표 미달** — 대응: 먼저 합성 데이터로 렌더링을 완성하고, 파서는 측정하며 개선. 목표 미달 시 수치를 그대로 보고.
  - **가산 블렌딩 누적 포화** — `R16Float`는 2048 근처부터 정밀도가 떨어짐. 대응: `R32Float` 사용(블렌딩 지원 여부를 기기에서 확인).
  - **점 크기** — `point_size`가 Retina 배율과 맞지 않을 수 있음. 대응: `contentScaleFactor` 반영.
